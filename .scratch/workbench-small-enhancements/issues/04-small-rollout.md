## Question

在活动提示、查找排序、产出来源的行为边界确定后，如何拆成小幅、可独立验证的实现批次，避免一次调整所有会话与工作台逻辑？

需要确定每批范围、先后关系、对应的增量 spec / 实施 ticket，以及最小必要验证；这是一张规划决策票，不是实施任务。

## Existing evidence

- 名称搜索、卡片运行计数与产出来源都能消费已有字段；未读共享涉及 Sidebar 和 AppShell，范围稍大。
- 三项本身没有必然的执行依赖。这里的 blocking 仅表示划分实现批次要消费前三张票的答案，不表示所有功能必须同时开发。
- 每批需同步 demo 镜像和三语言文案，并针对改变的外部行为验证。保持现有移动端 44px 控件、主题变量、文件路由与 composer draft 语义；开发不运行 `next build`。

## Candidate to discuss

先评估“名称搜索 + 运行计数”，再评估“产出来源展示”，最后接入“未读共享 + 已确定的最近活动行为”。若某个独立改动已经足够小，可单独交付。每批控制在已有前端与必要的纯 helper 上，发现需要新的 store/runtime 设计时回到相应决策票重新收敛。

以上是待前三票答案校正的候选顺序，尚未作为本票答案。

## Answer

Resolved: 2026-10-07，用户确认“按接入成本分三批”。前置三项行为决策已分别 resolved。

### 已确认的推进顺序

| 批次 | 实施范围 | 最小接入边界 |
| --- | --- | --- |
| 第一批：名称搜索与运行计数 | 名称搜索与现有状态过滤组合；卡片显示运行中会话数，零值隐藏 | WorkbenchView、纯 helper；消费已有目标与成员 `isRunning`，复用当前刷新 |
| 第二批：产出来源展示 | 文件名、路径/工作树、写入时间、来源会话入口及不可用说明 | WorkItemDetail、必要显示 helper；消费现有 Outputs/成员 DTO 和导航回调 |
| 第三批：未读共享与最近活动 | 卡片未读计数、只读共享、最近活动可选排序、当前视图偏好 | Sidebar → AppShell → Workbench 只读回调；列表派生排序，不迁移状态所有权 |

三批均沿用前三张决策票的最终 Answer，不重新解释其语义。上述是用户确认的交付顺序，而不是功能之间虚构的技术依赖；每批均能独立验证。第三批可以包含未读与排序两个小改动，但应分开验证它们的状态来源和列表行为。

### 实施交接形态

后续实施在新目录 `.scratch/workbench-enhancements/` 编写一个增量 `spec.md`，引用本地图及各 Answer；在其 `issues/` 下为三个批次分别创建“名称搜索与运行计数”“产出来源展示”“未读共享与最近活动”实施票。原 `.scratch/workbench/spec.md` 与已完成票保持现有生产行为的基线。

本地图中的票全部是决策票，不改成实现待办，也不因规划完成宣称生产功能已完成。本轮不创建新的实施待办或修改生产代码。

### 每批的交付门槛

- 应用与 demo 同步，en / zh-CN / zh-TW 文案一致；沿用现有主题、原生组件与移动端 44px 点击目标。
- 运行应用与 demo 类型检查、Lint，以及与本批新增外部行为对应的必要测试；浏览器核对桌面/手机和深浅主题。无关行为不增加镜像式测试，开发不运行 `next build`。
- 第一批重点验证名称/状态交集、无匹配、计数与完成状态独立；第二批重点验证不同工作树的同名文件、文件/来源导航、缺失/不可用和部分结果；第三批重点验证原生未读清除/抑制、Association 变化、时间回退与稳定排序、退出/刷新后恢复默认。
- 最终集成验证覆盖切换工作台/聊天时的草稿、已选中会话、文件面板 cwd/worktree 与原生会话导航；必要的完整回归在集成时运行。
- 每批只触及既有前端与纯 helper。若事实证明需要扩大 store、session 格式、权限或 runtime 契约，先暂停该扩大范围并另行决策，不能以“顺手重构”带入本轮。

### 路线已清晰

多工作树同名文件由路径与目录常显解决；信息密度沿用现有列表、可换行路径与可见说明，不新增看板或复杂布局。本轮没有剩余的设计前置问题；具体代码选择及测试中发现的缺陷属于后续实施与验收。
