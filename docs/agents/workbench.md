# Workbench and Work Items

Contract: `.scratch/workbench/spec.md` and tickets 01–05. Vocabulary: `CONTEXT.md`; direction: ADR 0007. Workbench organizes sessions and current files; it adds no agent permission policy.

## Authoritative store and Association

- `lib/work-items.ts` owns `getAgentDir()/pi-web-work-items.json` (version 1, `PI_CODING_AGENT_DIR` supported). Cache is a validated snapshot, not the authority. Only ENOENT initializes empty; malformed/unknown schema, duplicate item ids, read/stat failures, and write failures preserve the existing bytes and surface errors.
- Each mutation serializes by path in this process, then takes proper-lockfile's `realpath:false` lock on the destination name. The destination need not exist. Read it after acquiring the lock; writing a placeholder before the lock and then trusting `createdHere` loses another process's first write. Atomic writes use the private 0600 helper.
- One session has at most one Work Item. A hand-edited duplicate Association is resolved by smallest Work Item id on reads without rewriting disk; successful mutations normalize it. Save-as validates all initial sessions and persists item+Association together. A move compares `expectedWorkItemId` under the lock; stale confirmation is a 409, and the UI must obtain a fresh confirmation.
- `sessionCheckoutRoots` is optional version-1 Association metadata, captured from server-validated Git checkouts at save/attach/create/fork. It preserves the original boundary for subdirectory writes after checkout removal. Move/detach/delete/conflict normalization maintain its session keys. Reattaching to the current target can backfill an older record while the checkout exists, without changing `updatedAt`; reads never backfill. An old record whose checkout was already removed has only its recorded cwd as provable fallback coverage.
- `work-item-sessions.ts` inspects persisted metadata and live wrappers, including transient ones, without creating AgentSessions. Catalogue absence is insufficient: a full header discovery must confirm absence. Failed/partial/unreadable discovery retains unavailable Associations. Reads filter confirmed-absent members only in the returned view; cascade-delete cleanup strips every actually deleted id. Empty items survive.
- Reuse existing Project grouping. Linked worktree top-levels share the main Project key; existing subdirectory Project identities remain as before. Identity equality never replaces the session cwd used to resolve a file or choose its actual checkout.

## Creation, fork and recovery

- Associated chat controls show the current Work Item, Change Work Item and Detach. The chooser and confirm action appear only after Change; Cancel/Escape collapse without writing, and successful association collapses and clears the choice. Moves still require confirmation with the current owner and `expectedWorkItemId`; a conflict keeps the chooser open for a fresh confirmation.

- New-session draft intent is keyed to that draft, with separate parked keys for Work Items sharing a Project. Parking/rekeying carries text, attachments, and intent together. Opening another goal does not reuse a different goal's draft. Switching views keeps ChatWindow mounted but hidden, so native abandoned-draft cleanup cannot delete an unsent composer.
- `/api/agent/new` validates the goal/Project before runtime creation, then settles Association before success or a first prompt. System/Tools `ensure_session` carries the same intent. Client promotion selects/refreshes; it is not the writer of authoritative Association.
- `AgentSessionWrapper.send()` wraps native `fork`, `fork_branch`, and `clone` using `forkWithWorkItemAssociation`. Native fork isolation in `sessions.md` still applies. Capture the source owner before creating, retain the source, and revalidate that owner inside the locked inheritance write. In-session navigation retains the existing Association; subagents inherit none automatically.
- The native session and JSON store are separate writes. A partial failure returns `association_pending`, real `sessionId`, intended `workItemId`, cause and status. The live process retains the recovery intent and gates prompt dispatch for that generated id. Retry (`recover:true` on the Association endpoint) revalidates the original fork source; explicit Attach is a separate user choice. Neither action repeats native creation/fork or resends a prompt. Successful recovery/attach clears the gate.
- A process crash between writes can leave a persisted unassociated session for explicit attach. Empty unpersisted runtimes follow native restart behavior; this feature promises no cross-file transaction or recovery of an in-flight model run.
- Completion is organizational. Continuing, creating, moving, or forking sessions does not reopen a completed item. Only explicit status actions change status; native tool presets and permissions remain authoritative.

## Outputs and file access

- `work-item-outputs.ts` scans raw message entries across all branches and compacted history. Top-level local pi write/edit and the supported apply_patch contract require paired successful results. Structured successful nested pi write/edit calls count even when their parent script failed. Missing/unfinished nested evidence is explicitly partial.
- Shell-created files, remote/MCP name variants without nested local coding-write evidence, and nested patches lacking applied-file results are excluded. Reply prose, script strings and `details.calls` display previews are not write evidence. Supported writes before an explicit attach are included. Detach/delete removes only that source's contribution; there are no retained file bytes or artifact versions.
- Bounds: 100 sessions, 16 MiB per source, 32 MiB aggregate fresh reads, 1 MiB per line, 3 s scan time, 12 s overall projection deadline, 200 response rows and 512 KiB response size. Extraction cache is fingerprinted, bounded to 100 sources / 4 MiB, and incomplete limit-limited scans are not cached as complete. Every limit/unavailable/access omission sets `incomplete` and a visible reason, even for an empty result.
- Relative tool paths resolve against source cwd. Rows preserve source session/cwd and actual checkout root, and Windows-aware path equality deduplicates them. Identical relative names in different worktrees stay distinct. After checkout removal, the saved boundary permits path-only missing rows (including siblings of a subdirectory cwd) only when checkout/cwd/file are absent and existing allowed roots still authorize the path. Existing paths always need the current Project and resolved-link checks. This metadata never grants file access or rebinds a removed path to the main checkout.
- Current file/Git state is queried on every refresh independently of transcript evidence cache. Status is queried at the actual checkout root so sibling writes from a subdirectory are visible. Tabs retain that root independently of the selected chat Project. Missing files remain paths without open/diff actions; clean, untracked/ignored, non-Git, unavailable, and unsupported-diff states are visible.
- Diffs show current working-tree changes, which may include another goal/session/user's work. A clean file is not proof of a retained committed output, and a committed diff is not available through this feature.

## UI, demo and verification

- All strings are in `workbench.*` for en, zh-CN and zh-TW. Mobile uses wrapping controls/paths and 44 px targets. Keyboard focus is visible; state/conflict/recovery/partial-result copy remains visible on touch screens.
- Buttons use `SettingsUi.ConfigButton`, including its `--accent-contrast` foreground, focus and disabled states; filters reuse the shared segmented control styles. Save-as is an inline named form, prefilled from the session title. Opening/cancelling writes nothing, Escape returns focus to the trigger, and a failed save retains the entered name and shows the error. Explicit submit still creates the Work Item and Association atomically.
- While the Workbench is visible it refreshes the existing catalogue/running registry every 5 s, including initially idle items. Member activity/running transitions invalidate detail Outputs. Hidden tabs stop polling; detail entry, membership edits and manual Refresh also invalidate evidence/file states. Resuming the already-selected session clears `view=workbench` without remounting the composer.
- `demo/mock/work-items.ts` supplies in-memory list/detail/Association/Outputs state. Demo components mirror the app; retain the existing base-path, preview and Full history changes in demo AppShell. No server store/SDK code enters its client bundle.
- Tests cover the store, Association API, route first-prompt gating, draft isolation, fork conflict/recovery and deletion, raw evidence and real Git-state refresh. `e2e/workbench.mjs` extends the existing runner with real fixture sessions and two checkouts at desktop/mobile widths. Run with `E2E_BROWSER_CHANNEL=msedge` to use installed Edge when bundled Chromium is unavailable. Never run `next build` in the development checkout.
- `npm test` uses `scripts/test.mjs`. On Windows, fixtures use a canonical temporary parent outside the checkout so they inherit neither its Git repository nor its SDK dependencies. The runner prefers the installed Git Bash over the WSL shim and caps test-file concurrency at 4. SSR tests use matching extensionless imports for shared contexts; source assertions normalize CRLF; MCP fixtures await shutdown; native PTY startup and lease-clock behavior are tested separately. Full behavior assertions remain enabled.
